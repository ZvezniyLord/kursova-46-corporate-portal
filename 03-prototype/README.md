# 03-prototype — Емпіричний прототип корпоративного порталу (демо)

Статичний HTML/CSS/JS-прототип корпоративного порталу для навчального набору
"Управління ІТ-проєктом створення корпоративного порталу підприємства" (О3/prototyp).

## Що вбудовано

| Екран | Файл | Вимога (RBAC) | Відмітка |
|---|---|---|---|
| Вхід (mock) | `index.html` | `login` | UI-імітація + демо-аккаунти |
| Панель привітання | `dashboard.html` | `view_dashboard` | показує роль, плани, елементи |
| Оголошення | `announcements.html` | `view_announcements` | фільтри категорії, адмін-форма додавання |
| Документи | `documents.html` | `view_documents` | пошук/фільтри/таблиця |
| Довідник | `directory.html` | `view_directory` | пошук/фільтр, адмін-форма додавання |
| Ролі та матриця | `roles.html` | `manage_roles` | RBAC-матриця + статус сеансу |

Тривалість: прототип — **UI-демо**. У реальній реалізації всі ці екрани містять
запити до API, сесій та БД. Немає безпечного входу, JWT/OAuth, авторизації на стороні
сервера чи сховища стану.

## Запуск (безбілдорова статична сервер)

1. Відкрийте термінал у корені каталогу `03-prototype/` (тільки корінь!).
2. Запустіть сервер статичних файлів:

   ```bash
   npx serve -l 3000          # Node/npx
   python -m http.server 3000 # Python
   ```

3. Відкрийте у браузері `http://localhost:3000/`.

Альтернатива: відкрити будь-який `*.html` файл прямо з диску (для демо це має працювати
також, оскільки `window.PortalDemoData` і `PortalApp` експортуються в глобальний
`window`). Але **завжди використовуйте локальний сервер** для консистентного тесту.

## Демо-контент (синтетичний)

- 10 синтетичних співробітників (прізвища, ролі, відділи, e-mail, телефон, `avatar`)
- 10 оголошень (категорії: `загальна`, `графік`, `платні умови`, `навчання`,
  `кампанія`, `методичка`, `акуція`, `зустріч`)
- 14 документів (категорії, теги, відділи, власники, розміри)
- 4 ролі: `guest`, `user`, `admin`, `superadmin` з матрицею дозволів

### Демо-логіни

- `demo@firm.ua` / пароль `DemoPort1!` (будь-яке значення)
- Роль обирається в селекті на сторінці входу. Через `sessionStorage` (`portal_demo_role`)
  імітується активна роль. **Це не безпечний логін.**

## Відомі обмеження (honest limitations)

1. **UI-демо RBAC.** Керування дозволами відбувається лише в браузері. Безпека не
   реалізована. Статичний вид не перевіряє авторизацію на стороні сервера.
2. **Немає реального автентифікаційного бекенду.** Усі облікові записи — симуляція.
3. **Через видимі даних** автоматизовані перевірки не можуть оцінити продуктивність,
   доступність, масштабованість.
4. **Тільки статичний контент.** Старінги, оновлення, публікації не зберігаються на
   сервері.
5. **Тестові дані не мають результативності.** Немає реальних електронних листів,
   відгуків або журналів подій.
6. **Шифрування, куки, CSRF, rate limiting** — не реалізовано (UI-мета).
7. **Часова лінійка.** Додані оголошення/співробітники зберігаються лише в пам'яті
   браузера модуля (локальному `window.PortalDemoData`), і перед відкриттям сторінки
   втрачаються.

## Smoke check (нормативний)

Скрипт `docs/smoke-check.js` — **Node-скрипт** для перевірки артефактів:

1. існують усі HTML/JS/CSS файли;
2. синтаксис усіх JS файлів (через `node --check`);
3. HTML-сайт посилається на наявні CSS/JS;
4. `PortalDemoData` завантажується у sandbox, і `PortalApp.can()` відповідає очікуваному
   для кожної ролі (row of the RBAC matrix).

Виконайте:

```bash
node docs/smoke-check.js
```

### Що UAT може оцінити (і що ні)

**UAT може:**
- перевірити зовнішній вигляд та навігацію;
- переконатися, що екрани показують відповідно до ролі (UI-темплейт);
- пройти репродуктивні сценарії входу/доступу;
- перевірити, що додавання декларацій проходить клієнтсько;

**UAT НЕ може:**
- підтвердити продуктивність, безпеку, доступність, масштабованість;
- підтвердити, що механізм RBAC працює за межам браузера;
- перевірити реальні облікові записи, JWT, ідентичні послуги або логування.

## Архітектура прототипу (євристично)

- `demo-data.js` — синтетичні дані (DRY, одне джерело).
- `app.js` — загальний рушій: збереження сеансу (MOCK), RBAC `can(role, perm)`,
  `requireAuth`, `requirePermission`, `showAccessDenied`.
- `nav.js` — відображення навігації та user-chip за рольовим правилом.
- `*.js` (сторінки) — логіка кожного екрану з викликом `requireAuth` /
  `requirePermission`.

## Пріоритетність та статус

| Артефакт | Статус | Примітка |
|---|---|---|
| Скелет прототипу (HTML/CSS/JS) | `REAL` | запущено локально для перевірки |
| Демо-контент | `REAL` (синтетичний) | зазначено явно |
| Smoke-check `docs/smoke-check.js` | `REAL` | окремий Node-скрипт |
| Преемський тест середовища (продакшн) | `NOT_PERFORMED` | UI-прототип не є продуктом |

> Пам'ятайте: UAT на статичному прототипі передбачає тільки вигляд та побачення органів, а
> не бізнес-результати.
