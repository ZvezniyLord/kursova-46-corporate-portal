# AGENT5_BOT_MODE_HOTFIX.md — виправлення запуску платних Subagents

## Причина помилки

Стара інструкція неправильно трактувала завдання: `delegate_task(role="orchestrator")` створює **тимчасові субагентні завдання**, а не **постійні незалежні Bots**. За типовою конфігурацією делегування може успадковувати провайдера/модель головного агента; тому запуск у дорогому сеансі може запустити дорогу модель і в дочірніх завданнях.

**Правильна вимога:** головний Agent 5 + **рівно чотири нові постійні Bot Mode профілі**, кожен із власною явно закріпленою безкоштовною моделлю; інструкції і запуск лише після верифікації.

## Негайна дія для оператора

1. У вікні, де видно `GPT-6-luna` і активні Subagents, натисни **Stop** для поточного ходу. За потреби перевір статус підзадач: зупинка головного ходу не завжди гарантує, що всі фонові виклики скасовані. Не видаляй готові файли чи профілі.
2. Через селектор моделі в чаті зміни **модель самого головного бота** на реально безкоштовну локальну/підтверджену free-tier. Сеанс на невідомій або платній моделі більше не продовжуй.
3. Прочитай актуальну версію `AGENTS.md` і цей файл; стара інструкція `delegate_task` скасована.
4. Переконайся, що у локального Hermes є дійсно безкоштовний модельний endpoint і hard cap на витрати/білінг. Якщо безпечного безкоштовного провайдера немає — `BLOCKED`, нічого не запускати.

## Виконавець: Agent 5 (виконання лише після зміни моделі)

**Обов'язково прочитай встановлений скіл `hermes-agent`** (розділи про Bot Mode, профілі, скіли, інструменти й моделі) та звір команди з офіційною документацією поточної версії.

**Незмінні заборони:** не запускати `delegate_task` замість створення Bots; не клонувати платні профілі; не залишати невстановленою модель у новому боті; не користуватися платним fallback; не видавати «є 4 боти» за факт без профілів у BOTS і `hermes profile show`.

### Як створювати

**Рекомендований спосіб — Hermes Desktop:** `BOTS → + → New Agent → Advanced → Fresh profile`.
Для кожного бота:

1. Задай унікальний **Name** як у таблиці, зрозумілий **Title**, роль у **Description**.
2. У **Model & provider pin** вибери конкретну **підтверджено безкоштовну** модель. Не залишай поле порожнім: Hermes може успадкувати платну модель головного профілю.
3. **Copy API keys from main profile** — вимкни, якщо основний профіль має платні API-ключі (типове значення в UI може бути увімкнено). Перевір окремо успадкування OAuth і fallback. Без дійсно безпечної конфігурації не запускай інференс.
4. Додай власний `SOUL.md` (призначення + правила із `AGENTS.md`) і необхідні Skills/Tools/MCP. Не клонуй платний профіль без аудиту.
5. Перевір фактичну появу в **BOTS**, конфігурацію моделі та наявність потрібних skills.
6. Повтори для рівно чотирьох профілів. За відсутності доступу до Desktop Agent 5 **не має права** симулювати створення.

**CLI-альтернатива**, якщо цей Hermes дає агенту доступ до локального термінала і його CLI підтримує команди:

```bash
hermes profile list
hermes profile create course46-mpp --no-credentials
hermes profile create course46-jira --no-credentials
hermes profile create course46-prototype --no-credentials
hermes profile create course46-uat --no-credentials

# ДО ПЕРШОГО ЗАПУСКУ налаштувати у кожному профілі
# конкретні provider/model із доступного free/local каталогу:
hermes -p course46-mpp config edit
hermes -p course46-jira config edit
hermes -p course46-prototype config edit
hermes -p course46-uat config edit

hermes profile show course46-mpp
hermes profile show course46-jira
hermes profile show course46-prototype
hermes profile show course46-uat
```

Команди створення застосовуй **лише якщо таких профілів іще немає**. CLI-профіль може вимагати додаткової конфігурації Desktop Bot Chat/метаданих. Остаточна перевірка — кожен з 4 ботів **видимий у BOTS**. Якщо `--no-credentials` не підтримується локальною версією, не використовуй небезпечний fallback — перевір `hermes profile create --help` і обери безпечний GUI.

### Оркестрація між постійними Bots

Після перевірки **5/5** моделей (головний Agent 5 і чотири нових):
- У канонічному `Bot Chat` Agent 5 передає доручення кожному через `message_agent(target="course46-mpp", message="...")`, аналогічно для інших, якщо інструмент доступний.
- Альтернативи: `@course46-mpp` і т. д. у Bot Mode; пряме доручення в кожному постійному Bot Chat; керований профільний CLI.
- Якщо `message_agent` недоступний у цій сесії, перевір документацію про канонічний Bot Chat і прапорець `bot_mode_protocol`; не підміняй це `delegate_task`.
- Субагентів усередині дочірніх Bots запускати **лише після окремої перевірки global `delegation.model`/провайдера**, щоб не був успадкований платний endpoint. В іншому разі дочірній бот виконує свій обсяг власними інструментами.

### Gates

**ZERO-COST GATE — перед будь-якою генерацією тексту:**
- [ ] Головний Agent 5 на підтвердженій free/local моделі.
- [ ] `course46-mpp` існує як постійний профіль, модель зафіксована, платний fallback вимкнено.
- [ ] `course46-jira` — те саме.
- [ ] `course46-prototype` — те саме.
- [ ] `course46-uat` — те саме.
- [ ] Усі чотири видно у BOTS.
- [ ] Скіл `hermes-agent` прочитано, конкретні інструменти створення профілів підтверджені.
- [ ] Збережено `docs/bot-roster.md` без секретів.

**Після gate:** Agent 5 створює єдиний контракт вимог і трасування, передає завдання спеціалістам і пише наукову курсову за `docs/AGENT5_ACADEMIC_CONTRACT.md`. Обов'язкові Moodle-артефакти і правила доброчесності залишаються незмінними. Репозиторій лишається **публічним**.

## Короткий коригувальний запит до Agent 5

> STOP: попереднє делегування було помилковим. `delegate_task` створив тимчасові Subagents на невідповідній моделі замість чотирьох постійних безкоштовних Bots. Не продовжуй поточні субагентні завдання, не роби платних API-запитів. Переконайся, що твоя поточна модель теж безкоштовна (інакше припини виконання). Прочитай ОНОВЛЕНІ `AGENTS.md` та `docs/AGENT5_BOT_MODE_HOTFIX.md`; прочитай встановлений скіл `hermes-agent`, офіційну Bot Mode та Profiles документацію. Інвентаризуй наявні профілі. Через BOTS / New Agent / Advanced / Fresh profile (або безпечний профільний CLI) створи рівно чотири постійні профілі `course46-mpp`, `course46-jira`, `course46-prototype`, `course46-uat`. Кожному явно закріпи реально перевірену free/local provider/model, не успадковуй GPT-6-luna, не копіюй платні API-ключі, не дозволяй billable fallback. Перевір чотири профілі у BOTS та `hermes profile show`, зафіксуй `docs/bot-roster.md`. НІЯКОГО `delegate_task` як заміни профілів. Запуск курсової дозволений лише після проходження zero-cost gate 5/5. Якщо ти не можеш створювати профілі локально, припини роботу та надай ручні кроки оператору, не імітуй виконання.
