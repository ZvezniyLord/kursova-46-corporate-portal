# Запуск Agent 5 у Hermes Agent

**Статус:** цей документ — інструкція запуску. Розміщення файлів у GitHub **не запускає** Hermes, не створює Jira або `.mpp` автоматично.

## 1. Відкрити репозиторій локально

Якщо репозиторій уже клонований, просто відкрий його кореневу папку. Інакше:

```bash
git clone https://github.com/ZvezniyLord/kursova-46-corporate-portal.git
cd kursova-46-corporate-portal
```

Потрібні встановлений і налаштований Hermes Agent та доступ до **реально безкоштовних** моделей. Перевір локально:

```bash
hermes --help
```

Потім запусти Hermes **з кореня репозиторію**:

```bash
hermes
```

Hermes підтримує проєктні контекстні файли `AGENTS.md`, однак вищопріоритетний файл `.hermes.md` у середовищі може змінити автоматичне завантаження. На початку сесії переконайся, що агент прочитав **саме цей `AGENTS.md`**, `docs/AGENT5_ACADEMIC_CONTRACT.md`, `docs/structure-and-requirements.md` і `docs/coursework-source-pack/README.md`.

## 2. Стартовий запит для головного Hermes

Скопіюй у чат Hermes:

> Ти Agent 5 — головний оркестратор курсової №46. Прочитай кореневий AGENTS.md, docs/AGENT5_ACADEMIC_CONTRACT.md, docs/structure-and-requirements.md, docs/coursework-source-pack/README.md, а також релевантні файли з COURSEWORK_SOURCE_PACK.md. Працюй у поточному публічному репозиторії; не створюй приватного. Використовуй лише фактично доступні безкоштовні локальні або безкоштовні віддалені моделі, без платного fallback. Перевір інструменти Hermes, конфігурацію делегування і ліміти. Спершу створи єдиний контракт проєкту, реєстр припущень, трасованість і маніфест доказів. Далі створи рівно чотири безпосередні дочірні оркестратори через реальний delegate_task із role=orchestrator: O1 MS Project/MPP, O2 Jira, O3 інтерактивний прототип, O4 UAT/QA. Кожному дай одні й ті самі вимоги та окремий каталог. За необхідності використай вкладене делегування лише в межах перевірених безкоштовних квот. Самостійно виконуй дослідження джерел, редактуру, зведення трьох розділів, формування DOCX і PDF та перевірку академічної доброчесності відповідно до універсального контракту. Усі розрахунки, IDs, ресурси та терміни мають збігатися. Не вигадуй .mpp, Jira, UAT, цитувань і скриншотів. Якщо інструменти чи безкоштовні моделі недоступні, чесно запиши BLOCKED; не видавай план за результат. Звітуй українською із посиланнями на фактичні файли й журнали запуску. Розпочни роботу.

## 3. Перед делегуванням

- Перевір, які локальні/безкоштовні моделі доступні. Не обирай модель лише тому, що вона має «free» у маркетинговій назві; перевір поточний тариф і квоту. Не логуй ключі.
- Перевір фактично доступний інструмент `delegate_task`. Назви полів і аргументи беруться з його поточної схеми, а не з уявного прикладу.
- Для чотирьох дочірніх **оркестраторів** і їхніх можливих дочірніх worker-агентів документована схема Hermes може вимагати:

```yaml
# Приклад локальних налаштувань ~/.hermes/config.yaml, НЕ готовий патч
delegation:
  orchestrator_enabled: true
  max_spawn_depth: 2
  max_concurrent_children: 4
```

Це **орієнтир для перевірки**, не команда самостійно перезаписувати конфігурацію. Перевір версію та навантаження, отримай дозвіл власника для зміни глобальних параметрів. Якщо `max_concurrent_children` менший за 4, за можливості запускай доручення хвилями.

## 4. Критерії фактичного запуску

Запуск зараховується тільки якщо є: (1) фактичні IDs дочірніх завдань у Hermes; (2) підтверджені безкоштовні моделі; (3) файли `docs/project-contract.md`, `docs/assumptions-register.md`, `docs/traceability.csv`, `docs/evidence-manifest.md`; (4) результати 4 напрямів; (5) справжні артефакти та науково перевірена курсова. Сам `AGENTS.md` **не є свідченням запуску**.
