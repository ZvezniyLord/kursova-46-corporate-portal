# 04-uat — Перевірка приймання (UAT). Оновлений тест-кейси

**Рапорт:** 2026-10-23. Хоча всі UAT-кейси залишені **NOT_RUN**, перевірено *артефакт* прототипу (символьний smoke 15/15, статичний сервер HTTP 200 — див. секцію "Прототипний smoke (не UAT)"). **Формальне user acceptance не виконано** (NOT_PERFORMED). Немає fake PASS, немає вигаданих користувачів/підписів.

## 0. Стандартні статуси

| Стан | Значення |
|---|---|
| `NOT_RUN` | Сценарій написано, не запускався |
| `NOT_PERFORMED` | Формальне приймання не виконано (немає уповноваженого користувача/замовника) |
| `PASS` | Фактично запущено, отримано очікування (тільки для прототипного smoke) |
| `FAIL` | Фактично запущено, спотворено очікування |
| `BLOCKED` | Немає перевіреного артефакта/засобу; тест не можливо запустити |

## 2. Детальні тестові випадки (передумови / синтетичні дані / кроки / вимірювані очікувані результати)

### UAT-001 — Мок-автентифікація входу (REQ-001/US-001 / WBS-1.1) — Must — `NOT_RUN`
- **Передумоги:** локальний статичний сервер `03-prototype/` (npx serve -l 3000 або python -m http.server 3000); index.html; JS увімкнено; демо-дані `PortalDemoData`/`PortalApp` завантажуються.
- **Синтетичні дані:** лише один синтетичний акаунт `demo@firm.ua` (пароль `DemoPort1!` — будь-яке значення приймається у демо-режимі); селект ролей: `user`, `admin`, `superadmin`; спливаюче повідомлення "це не реальна аутентифікація".
- **Кроки:** 1) відкрити http://localhost:3000/; 2) переконатися, що є бейдж "Демо-режим" і текст "це не реальна аутентифікація"; 3) обраний роль `user`; 4) натиснути "Увійти (демо)"; 5) прочитати URL після перенаправлення; 6) прочитати `sessionStorage` ключ `portal_demo_role`.
- **Очікувані результати (вимірювані):** URL = `http://localhost:3000/dashboard.html`; `sessionStorage.portal_demo_role === "user"`; сторінка показує бейдж та підпис "це не реальна аутентифікація"; HTTP-код 200; немає редіректу на зовнішні host; пароль не перевіряється (люба стрічка допустима в демо).
- **Фактичний результат:** — (NOT_RUN)

## 3. Прототипний smoke (не UAT) — реальні результати

Виконано у цьому сесії, на локальному прототипі, без підзадач і зовнішніх сервісів:

- **SMOKE-001 (структура/артефакт):** `node 03-prototype/docs/smoke-check.js` → **PASS 15/15** (всі обов’язкові файли існують; JS-синтаксис для 9 файлів; HTML-залежності всіх 6 сторінок; RBAC матриця guest/user/admin/superadmin 3/3, 5/5, 11/11, 13/13; демо-функції пошуку запускаються). Експорт: `passed: 15/15`, `EXIT=0`.
- **SMOKE-002 (доставка):** Python статичний сервер на `127.0.0.1:8899` → HTTP **200** для 6 HTML сторінок + 10 JS/CSS ресурсів (full list of codes recorded); сервер зупинено після перевірки.
- **Межа застосовності:** ці перевірки — перевірка артефактів (відсутність відсутніх файлів, синтаксис, локальні посилання, локальна RBAC таблиця, функції пошуку). **Не підтверджують** автентифікацію на бекенді, продуктивність, доступність, UI-прохід реальними ключовими органами.
